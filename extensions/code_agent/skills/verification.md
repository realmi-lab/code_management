카탈로그 답변 검증 절차입니다. 이 파일은 자유 생성 프롬프트가 아니라 검증 실행 계약입니다.
1. 출력 전체의 개인정보 노출을 검사합니다. 입력 마스킹이 등록 DB 원문을 바꾸면 안 됩니다.
2. 설명의 등록 사실 근거는 catalog와 rule_comparison입니다. 사용자 질문·대화·실패한 답변은 등록 사실의 근거가 아닙니다. 모든 검색 후보·필드·원문·조건을 보존합니다.
3. 코드·등록 문구·메뉴·노출 조건의 명시적 인용은 해당 코드의 DB 원문과 연결해 검사합니다. 다른 후보의 값이 근거 전체에 있다는 이유로 잘못 인용한 값을 허용하지 않습니다. 모든 질문과 코드에 같은 규칙을 적용합니다.
4. 원본 수치 검사와 확장 수치·단위 검사를 모두 수행합니다. 다른 코드의 숫자나 이후/이내 조건을 옮겨 쓰면 안 됩니다.
5. 충실도 점수 0.9 이상과 FAITHFUL을 요구합니다. 형식 누락·중복 필드·범위 이탈을 통과로 해석하지 않습니다.
6. 근거 점수 0.8 이상과 PASS를 요구합니다. 충실도·근거 두 판정 모두 통과해야 합니다.
7. 검증 서비스 오류·잘못된 형식은 오류로 중단합니다. 다른 모델로 몰래 전환하거나 오류를 내용 거절로 재분류하지 않습니다.
8. 설명의 형식·수치·근거 내용 거절만 동일 근거로 최대 한 번 재작성합니다. 같은 거절 답변은 재채점하지 않습니다. 초안·개인정보·입력 방어·판정 서비스 오류는 자동 재작성하지 않습니다.
어떤 특정 질문·코드·수치를 정답으로 지정하지 않습니다. 검증은 정식 등록이나 재사용 승인 권한이 아닙니다.
