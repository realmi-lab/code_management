# 버그 수정 및 코드 최적화

검증일: 2026-09-17. 대상: `/shared/code_management`.

## 수정한 문제

- AI 응답의 content가 null·배열 등 잘못된 형태일 때 서버 오류 대신 원문 유지/기본 검색 안내를 반환합니다. HTTP 응답 크기를 제한하고 Command Code 취소·출력 초과 시 프로세스와 파이프 작업을 정리합니다.
- 동시에 같은 질문을 검색하면 모델 호출을 공유합니다. 기존 5분 캐시와 DeepSeek V4.1 Flash / Low 설정을 유지합니다.
- 모델을 기다리는 동안 목록이 수정되거나 폐기되면 최신 목록을 다시 읽습니다. 검색 결과·목록 개수·버전을 같은 DB 스냅샷에서 가져옵니다.
- 화면·예시/실제 목록·접속 키가 바뀐 뒤 도착한 응답이 현재 화면을 덮어쓰지 않습니다. 창 닫기와 잠금은 진행 중 응답을 무효화하고 표시 중인 자료를 지웁니다. 초안 저장 중 중복 제출을 차단합니다.
- 파일을 바꾸면 이전 미리보기를 무효화합니다. 모든 항목이 기존 목록과 같아도 확인을 완료할 수 있어 등록 초안 연결을 진행할 수 있습니다.
- 같은 초안 표시가 여러 코드에 있으면 가져오기 파일과 문구가 다르더라도 자동 연결을 막습니다. 등록 요청 재실행은 개정·변경 이력을 중복 증가시키지 않습니다.
- XLSX 중복/잘못된 행·셀 좌표와 음수 공유 문자열 참조를 거절합니다. 병합된 메뉴·조건의 수식 캐시값을 원문으로 받지 않으며 실제 원본 셀 위치를 기록합니다.
- 원본 파일 저장에 실패하면 확정 가능한 가져오기 기록이 남지 않습니다. 파일 파싱·저장을 작업 스레드로 옮겨 비동기 요청 처리를 막지 않게 했습니다.
- 비ASCII 인증 헤더는 정상적으로 401 처리하고, 공백뿐인 문구 비교는 422로 거절합니다.

## 최적화

- 전체 목록을 Python 객체로 읽던 집계·페이지 조회를 SQL 집계와 LIMIT/OFFSET으로 변경했습니다. Unicode 대소문자와 문자 그대로의 부분 검색 동작을 유지합니다.
- 목록 수 조회와 초안·이력 인덱스를 추가했습니다. 외부 등록 후보마다 가져오기 기록을 다시 조회하던 반복을 제거했습니다.
- 검색어와 문구의 정규화된 검색 특징을 제한된 메모리 캐시에 보관하고 상위 80개 후보만 선별 정렬합니다.
- 업로드 파일 해시는 파일당 한 번 계산합니다. 같은 문구 경고는 중복 제거 후 최대 20개 코드와 전체 개수를 반환합니다.

합성 자료 10,000건, 7회 중앙값으로 측정한 **DB 처리 구간** 결과입니다. 앱 전체 HTTP 응답 시간이나 모든 검색 조건에 대한 수치가 아닙니다.

| 처리 | 이전 | 변경 후 |
|---|---:|---:|
| 목록 집계 | 42.092ms | 0.596ms |
| 30건 페이지 조회 | 40.582ms | 0.495ms |

측정 스크립트: `scripts/benchmark_db.py`. 결과: `docs/optimization-benchmark.json`.

- 자동 테스트 **129개 통과**, 실패/오류/건너뜀 0개. 이번 수정 회귀 테스트 39개 포함 (`bugfix-tests.xml`).
- 기존 HTTP 브라우저 확인 **7개** 통과: 초안 작성·수정, 엑셀 요청·가져오기·수동 연결, AI 검색 UI/기본 검색, 모바일 포함 (`completion-browser-check.json`). 임시 DB와 모의 모델 사용.
- 지연 응답·중복 제출·파일 변경·창 닫기·잠금 브라우저 회귀 확인 **11개** 통과, JavaScript 오류 0개 (`bugfix-browser-check.json`). 임시 DB, 모델 호출 없음.
- 두 브라우저 검사는 실제 HTTP와 별도 Chromium 컨텍스트를 사용했으며 offline harness를 사용하지 않았습니다.
