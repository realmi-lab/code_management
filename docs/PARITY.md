# UrstoryRAG 재사용과 추가·변경 범위

## 전체 원본 유지

공식 저장소의 고정 커밋 `75661c676aec650e52f75dd068b687a4cb6a63b7`, Git tree `6e5ebcef24cfc575f5659329d946cc56c103c9ca`를 그대로 내려받아 `upstream/`에 보존한다. 원본 Next.js, FastAPI, RAG 파이프라인, 문서 처리, 인증·관리, 평가·모니터링, 테스트·문서·라이선스를 일부 모듈로 대체하지 않는다.

현재 ZIP은 전체 원본 다운로드 전이다. 설치 시 무결성 검사를 통과한 원본만 빌드한다. 이 환경에서 원본 tree 전체 확보/검증 완료를 주장하지 않는다.

## 실제 통합 코드

- 원본 app에 확장 API를 붙이는 `extensions/code_agent/entrypoint.py`.
- 원본 로그인으로 연동되는 `extensions/frontend/src/app/codes/page.tsx`와 동일 출처 내장 UI.
- 원본 `HybridSearchOrchestrator`, 벡터/Nori 엔진, 임베딩/LLM, 한국어 리랭커를 호출하는 `gateway.py`.
- 원본 Celery 앱에 카탈로그 태스크를 추가하는 `worker.py`.
- PostgreSQL 카탈로그, 원문·버전·승인/감사, 전용 PGVector/Nori 스냅샷, 대화별 상태·초안.

## 변경·의도적인 차이

일반 문서 질문과 알림 코드 질문은 같은 검색 구성 요소를 사용하되 데이터 인덱스와 최종 답변 방식이 다르다. 알림 번호/원문은 DB가 정답이며 최종 AI 설명은 별도 제한 프롬프트로 생성한다. 원본 생성 후 가드레일 전체를 카탈로그가 그대로 통과한다고 설명하지 않는다.

원본 컨테이너 사본에 검색 캐시, 초기 LLM 설정, 평가 워커 연결/인증/오류, 문서 삭제 후 검색 잔존 관련 패치를 적용한다. 원본 알고리즘 전체를 새로 쓴 것이 아니다. 빌드 패치는 원본 계약이 달라지면 중단하고 변경 전후 해시를 기록한다.

배포 토폴로지는 원본의 외부 공유 인프라 대신 프로젝트 전용 서비스를 사용한다. 따라서 모든 파일/배포/행동이 원본과 바이트 단위로 같다는 뜻은 아니다. 원본의 일반 문서·평가·계정·설정·모니터링 화면은 남아 있다.

## 미검증 범위

실제 원본 전체 다운로드, 이미지 빌드, Next 전체 빌드/원본 로그인, PostgreSQL/ES/Redis/Celery/Langfuse 통합 기동, 실제 모델 의미 검색·생성·평가 품질은 아직 확인하지 못했다. API와 화면 검사에서 대역을 사용한 부분은 TEST_REPORT.md에 구분했다. 원본 README 성능 수치를 이번 앱의 측정값으로 사용하지 않는다.

기존 `catalog_legacy/`는 기본 실행에 사용하지 않는다. 새 확장 코드가 실제 통합 구현이며 이전 SQLite 자료는 공식 엑셀 재가져오기로 옮겨야 한다.
