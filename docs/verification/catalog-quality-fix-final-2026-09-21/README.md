# 알림 코드 검색·설명 수정 결과

기존 68문항 평가에서 실패한 2·5·7·27·67번을 최종 수정본에서 각 두 번 실행했다. 실제 합성 DB와 모델을 호출했으며, 총 10회 모두 답변에 성공하고 정답 코드를 첫 번째로 찾았다.

## 변경

- 상황 설명을 초안 작성으로 오분류해도 명시적인 작성·수정 지시가 없으면 검색으로 처리한다. 인용 문구나 작성 금지 표현은 초안 지시로 취급하지 않는다. 명시적인 초안 작성과 샘플의 초안 금지, 정식 등록 승인 조건은 유지했다.
- 설명은 등록 코드·문구·메뉴·노출 조건을 중심으로 작성한다. 자료 부재나 UI 동작에 관한 추측을 유도하던 지시를 제거했다.
- 설명의 수치·근거 검증 실패 또는 JSON 스키마 오류에는 같은 근거로 한 번만 재생성을 허용한다. 오류 종류에 관계없이 최대 두 번 생성한다. 수정된 답변도 숫자 검사, 충실도 0.9, 근거 0.8 기준을 모두 통과해야 한다.
- 같은 거절 답변을 그대로 재생성하면 재채점하지 않는다. 검증 모델의 형식 오류·통신 오류와 입력/개인정보 차단을 재생성으로 우회하지 않는다. 초안에는 이 재생성을 적용하지 않는다.
- JSON 줄바꿈 이스케이프를 명시하고 스키마 오류 종류/필드만 기록한다. 답변 원문·개인정보·비밀값을 진단 로그에 추가하지 않았다.

정상 답변 10회 모두 숫자·충실도·근거 검사를 통과했고, 이 최종 실행에서는 자동 재생성 분기가 발생하지 않았다. 재생성의 횟수 제한·같은 답변 차단·재검증·재실패 차단은 대역 회귀 검사로 확인했다. 실제 검색 8회에서 PGVector, Elasticsearch Nori, RRF, 리랭커 실행이 확인됐다. 나머지 2회는 기존 검색 캐시를 사용했으며 답변은 새로 생성하고 검증했다.

마지막 문항의 별도 평가용 모델 호출이 한 번 실패했다. 앱 응답은 이미 성공한 상태였다. 저장한 답변을 변경하지 않고 평가 호출만 한 번 다시 실행해 93점을 받았다. 원래 오류가 포함된 results.json/summary.json은 보존하고, 추가 채점은 judge-retry.json에 분리했다. 위 최종 평균은 추가 채점을 포함한다.

## 자동·UI 확인

- 확장 도메인/API 검사 251개, 설치 검사 72개 통과. 외부 모델·검색·인증 대역 사용 범위는 각 검사에 명시돼 있다.
- native HTTP 10개 통과. 실제 loopback 전송이며 인증·모델은 대역이다.
- Python/JS 구문, TS/TSX 6개 파일 구문 통과. 고정 upstream 384개 파일 계약 유지.
- API 이미지 빌드·재기동 완료. 실행 중인 agent.py/gateway.py/safety.py의 SHA-256이 로컬 수정본과 일치했다.
- 실제 인앱 브라우저에서 회원가입 질문 → EX-0201과 DB 원문을 확인했다. 설명의 줄바꿈도 시각 확인했다.
