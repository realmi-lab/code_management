# 알림 코드 품질 평가 v1

## 사전 고정 조건

- 실제 로컬 API, PostgreSQL의 분리된 합성 샘플 목록을 사용합니다. 운영 데이터는 추가하거나 바꾸지 않습니다.
- 검색 전에 질문 12개와 질문별 대표 정답 코드 1개를 고정합니다 (`dataset.json`). 숫자 방향, 재발송, 가입, 약관, 중복 이메일, 화면 이탈, 네트워크, 권한을 포함합니다.
- 현재 설정을 그대로 사용합니다 (`settings.json`). 이 평가는 설정 간 A/B 비교가 아닙니다.
- Top-1, Hit@8, MRR@8은 고정된 대표 정답 코드 기준입니다. 다른 코드가 의미상 허용 가능한지는 별도 검토해야 하며 점수를 사후 조정하지 않습니다.
- 반환된 원문은 평가 시작 시 읽은 DB 원문과 정확히 비교합니다.
- 지연 시간에는 API 왕복과 서버 처리가 포함됩니다. 검색 trace의 캐시 적중 여부도 함께 보관합니다. 단일 실행 결과이며 p95나 운영 성능 보장은 하지 않습니다.
- 대표 질문 3개는 실제 모델을 통한 대화로도 실행합니다. 해당 대화는 demo 스코프에 남습니다. 모델 호출 오류도 결과에 포함합니다.
- 독립 LLM Judge와 RAGAS는 이 평가에 사용하지 않습니다. 원본의 GPT-4o 채점 점수와 직접 비교할 수 없습니다.
- 회사 데이터 정답률, 부정 질문의 오탐률, 권한 보안 감사, 장시간 부하 검증은 별도 범위입니다.

## 재현

프로젝트 루트에서 실행 중인 로컬 앱에 대해 `python3 integration_tests/live_catalog_quality.py`를 실행합니다. 선택된 AI 공급자의 실제 호출 비용이 발생할 수 있습니다. 이 스크립트는 설정을 변경하지 않습니다.

현재 실행 결과: `summary.json`, 개별 검색: `retrieval.json`, 대화 답변: `answers.json`.

완료된 두 답변을 직접 검토했으며 대표 코드와 인용 원문은 DB와 일치했습니다. 인증 질문은 30초 이후 대기와 30초 이내 완료의 방향 차이도 설명했습니다. 가입 질문은 기존 가입 번호와 재요청 대기 문구를 구분했습니다. 독립적인 평가 모델의 정량 점수는 아닙니다.

### 발견된 문제

`수정 내용을 저장하지 않은 채 화면을 나갈 때 확인`은 검색 API에서는 EX-0401을 1위로 찾았지만, 자동 대화에서는 초안 작성으로 분류되어 샘플 스코프의 초안 금지 규칙에 막혔습니다. 최초 실행은 HTTP 422였고, 별도 재확인에서도 동일하게 샘플 초안 금지 오류를 반환했습니다 (`failure-recheck.json`). 성공으로 재분류하지 않았습니다.

즉 검색 자체보다 **요청 의도 분류**가 개선 대상입니다. 이 평가에서는 분류 로직을 수정하거나 설정을 바꾸지 않았습니다. 이후 수정 시 동일 질문을 회귀 검사에 포함해야 합니다.

12개 질문은 정상 사례 위주의 소규모 1차 평가입니다. 회사 데이터 전체 정확도나 원본 공개 문서 평가의 92점과 동일한 의미가 아닙니다. 후속 평가는 오타, 여러 조건, 유사 숫자, 해당 없음, 후속 대화, 복수 정답을 사전에 포함해 확대해야 합니다.
