# 오류 검사 및 수정

범위: 현재 고정 원본과 확장, 설치/빌드, localhost 읽기 전용 API, 실제 Next 화면. 외부 LLM·임베딩 추론은 호출하지 않았다. 운영 목록·초안·설정을 테스트 자료로 변경하지 않았다.

## 재현 후 수정한 오류

1. 같은 설정 서비스에서 동시 저장 시 먼저 저장한 옵션이 덮어써졌다. 읽기/캐시 채우기/갱신을 잠금으로 직렬화했다. 원본 API의 공유 서비스가 다른 요청의 DB 세션으로 바뀌는 문제도 요청 수명 동안 별도 잠금으로 보호한다. 현재 단일 API 프로세스 범위의 조치이며 다중 서버 분산 쓰기 잠금은 아니다.
2. Redis 설정 값이 리스트·문자열 또는 잘못된 필드이면 설정 조회가 예외로 종료됐다. 캐시 형식과 정확한 버전 표식을 검증하고 손상된 캐시는 DB에서 다시 읽도록 수정했다.
3. 청크 크기/오버랩 저장값이 실제 문서 처리기에 전달되지 않았고, 재귀 분할기는 항상 고정 오버랩을 사용했다. 설정을 처리기→전략→분할기에 전달하고 0 오버랩도 반영했다. 문장 단위 분할이므로 문자 수와 정확히 같지는 않다. 기존 Sentence/Token은 원본에 전용 구현이 없는 자동 전략 별칭이므로 새 선택을 막고 실제 적용을 표시했다.
4. 실제 Haystack 분할기를 네트워크가 없는 컨테이너에서 실행하자 `punkt_tab` 자료 누락으로 긴 문서 처리가 실패했다. 공식 NLTK 자료를 고정 커밋과 SHA-256 검증으로 이미지에 포함했다. 실행 중 다운로드가 필요하지 않다.
5. 수동 스캔은 파일 수만 반환하는데 인덱싱이 시작된 것처럼 안내했다. 반환된 파일 개수와 인덱싱 미실행을 표시하도록 수정했다.
6. 최종 배포 검사에서 카탈로그 HTML과 JavaScript가 서로 다른 시점의 파일로 실행되어 없는 요소에 이벤트를 연결하다 실패했다. 최신 소스를 함께 재빌드했고, 호스트/실행 컨테이너의 두 파일 SHA-256 일치를 확인했다.

## 검사 결과

- 확장/도메인/API/패치 회귀: 최종 실행 183개 통과. DB·Redis·모델 대역을 사용하는 검사 포함.
- 설치/프론트 패치/청킹 계약: 67개 통과.
- 고정 원본 384개 파일과 모드 일치.
- 전체 API/작업자 이미지와 Next 이미지 빌드 통과.
- 합성 인증·모델을 사용하는 localhost HTTP 10개 및 오프라인 브리지 UI 14개 통과.
- 실제 분할기: 네트워크 없는 컨테이너에서 한국어/영어 합성 문장 각각 0 오버랩 20개, 반절 오버랩 39개, 헤더 분할 20개 생성 확인. 외부 모델 추론이나 DB 저장 없음.
- 실제 설정 API 읽기 요청 16개를 병렬 실행하여 모두 통과했다. 설정 저장은 테스트 대역에서 검증했고 운영 설정을 수정하지 않았다.
- 빌드된 Next 화면의 설정/감시/스캔/평가 검사 5개 통과. 상태 조회·변경·평가 자료는 대역이다.
- 최종 실제 화면 16곳 읽기 전용 검사 통과, JavaScript 오류 0건 및 HTTP 5xx 0건. 공급자 연결 상태 위젯은 대역으로 처리했다.

브라우저/최종 실행 증거는 [검사 폴더](verification/bug-audit-2026-09-21/)에 기록한다. 원본 감시 작업자의 DB·인덱싱 미구현, 백업 배포 연결, 실제 공급자/임베딩 종단간 품질 검증은 이번 완료 범위에 포함하지 않는다. 이 결과가 전체 앱에 버그가 없다는 보장은 아니다.
