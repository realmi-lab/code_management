# 작업 상태와 검증 기록

작성일: 2026-09-18 (KST)

## 핵심 결론

**원본 전체를 다운로드·검증·실행하는 설치 패키지를 작성했다. 이 환경에서 원본 저장소 전체의 다운로드와 Docker 실행은 성공하지 못했다.** 따라서 사용자의 요청인 원본 동일 기능의 실제 배포·동작 확인까지 완료된 상태는 아니다.

이 한계를 숨기고 이전처럼 일부 모듈만 재사용한 앱을 전체판이라고 설명하지 않는다. 원본 전체 소스는 사용 환경에서 `prepare` 또는 `start`가 성공하면 `upstream/`에 생성된다.

## 자동 테스트의 정확한 범위

테스트는 공식 소스를 가짜로 대신하는 앱 테스트가 아니다. 다음 설치 절차 자체를 검사한다.

- Git 트리: 바이너리·한글 파일명·실행 권한·symlink·정렬·누락·추가·수정 탐지.
- 압축 처리: 상위 경로 탈출·절대 경로·다중 루트·중복·hardlink·symlink 탈출·symlink 경유 쓰기·크기 제한 거절.
- 설치 안전성: 다운로드 실패 시 결과 폴더 미생성, 동시 작업 차단, 기존 소스 미덮어쓰기, 재실행 가능.
- 설정: 안전한 무작위 비밀값, 기존 값 보존, 파일 권한, 비밀값 로그 미출력, 포트·DB URL 검증.
- 실행 구성: 원본 전체 서비스 포함, API/워커 업로드 공유, 마이그레이션 선행, Nori 설치, 프론트 빌드 시 API 연결.
- HTTP 검사 도구: 모의 응답으로 원본 로그인·검색 계약과 실패 처리를 검사. **실제 HTTP·LLM 검증이 아님.**

## 수행하지 못한 것

- 사용자 Docker Local에 폴더 생성·파일 복사·실행.
- 이 작성 환경에서 원본 전체 파일을 실제 다운로드하여 원본 전체 tree를 검증.
- Docker 이미지 빌드, 의존성 설치, PostgreSQL/Alembic·Elasticsearch·Celery·Langfuse의 실제 통합 기동.
- 원본 백엔드 전체 테스트, 원본 프론트 빌드·브라우저 E2E.
- 실제 OpenAI 키로 임베딩·검색·리랭킹·생성·가드레일·RAGAS·모니터링 검증.
- 실제 회사 엑셀 기준 검색 정확도·부하·응답 시간·비용 검증.
- 원본 화면·계정·RAG 엔진에 기존 코드 카탈로그를 통합.
- 전체 보안 감사, 백업/복원 실행, 외부 공개 운영 승인.

## 차이를 남긴 이유

사용자의 “원본과 똑같이”를 원본 코드 전체를 그대로 실행한다는 의미로 반영했다. 다만 실제 실행 환경은 원본의 외부 공용 인프라 대신 독립 Compose로 보완했다. 기존 경량 앱은 손실 방지를 위해 보존했으며, 이 보존 자체를 원본과의 통합으로 부르지 않는다.

실제 모델·외부 의존성은 바뀔 수 있다. 동일 소스 사용은 동일 답변·동일 정확도·원본 저자의 성능 수치를 보장하지 않는다.
