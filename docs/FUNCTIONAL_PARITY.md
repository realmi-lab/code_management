# 고정 원본과 기능 연결 기준

비교 대상은 `urstory/urstory-rag` 커밋 `75661c676aec650e52f75dd068b687a4cb6a63b7`이다. 최신 GitHub 변경을 자동으로 가져오지 않는다. 원본 384개 파일을 유지하고 실행 사본의 변경은 `deploy/patch_*`에 기록한다.

사용자 요청에 따라 이번 작업에서는 외부 AI 호출·실제 임베딩 추론 검증을 수행하지 않는다. 로그인 없는 로컬 모드, AI 공급자 선택, 알림 코드 작업실은 기존 요청에 따른 확장으로 유지한다.

| 원본 기능 | 현재 연결 | 임베딩 연결 전 |
|---|---|---|
| 일반 문서 업로드·관리·재인덱싱 | 원본 API/화면/작업자 유지 | Nori 키워드 인덱스 사용 |
| 벡터·하이브리드·캐스케이딩 검색 | 원본 오케스트레이터/설정 유지 | 선택값 보관, 실제 실행은 키워드 모드 |
| HyDE·멀티쿼리·시맨틱 청킹 | 원본 구현과 옵션 보존 | 실행 제약만 적용, 저장값은 변경하지 않음 |

| OpenAI 호환 API·API 키 관리 | 원본 `/v1/chat/completions`와 관리 화면 유지 | 답변 생성에는 설정한 LLM 필요 |

| 알림 코드 검색·비교·초안·승인 | 원본 검색 엔진에 별도 카탈로그 범위 연결 | 등록 원문과 승인 절차 유지 |

## 설정 보관과 실제 실행 분리

원본 SettingsService의 DB/Redis/메모리 캐시에는 사용자가 지정한 설정을 보관한다. 요청마다 깊은 복사본에 공급자·임베딩 제약을 적용한다. 관리 화면의 GET/PATCH는 선택한 검색 모드, HyDE, 멀티쿼리, 청킹 전략을 유지한다. 임베딩을 연결하고 문서/카탈로그를 재인덱싱하면 저장한 옵션이 적용된다. local/OpenAI 선택이 검색 모드를 무조건 hybrid로 덮어쓰지 않는다.

이전 버전 Redis의 실행 제약이 섞인 캐시는 재사용하지 않는다. 다만 이전에 DB에 명시적으로 저장된 선택값이 사용자의 의도였는지 임의로 추정하여 복원하지 않는다. 관리 화면에서 원하는 값을 확인해 저장하면 된다.

## 원본 자체의 미완성 부분과 운영 연결 한계

소스가 보존되었다는 사실을 모든 기능이 완성되었다는 뜻으로 표시하지 않는다.

- 원본 감시 작업자는 파일 해시만 계산하며 DB 반영·인덱싱 부분은 주석, 삭제 작업은 `pass`이다. 수동 스캔도 파일 수만 반환한다. 이번에는 화면의 경로/폴링 입력을 실제 시작 API에 전달하고 미구현 부분을 표시했다. 자동 문서 동기화 완성으로 주장하지 않는다.
- 원본 백업/복구 스크립트도 보존되어 있으나 기본 컨테이너 이름과 Elasticsearch 스냅샷 저장소 설정은 현재 Compose와 다르다. 현재 배포용 백업/복구 자동화가 완료된 것은 아니다.
- 문항별 평가 점수가 반환되지 않거나 임베딩 지표가 생략되면 `미측정`으로 표시한다. 실제 측정값 0과 구분한다.

## 검증 범위

고정 원본에 패치를 적용한 SettingsService와 요청별 설정 처리를 테스트한다. DB/Redis 및 공급자는 테스트 대역이며 회사 자료와 분리한다. 실제 빌드한 Next 화면의 설정·감시 입력·평가 표시를 브라우저로 검사하되 저장/감시 시작/평가 응답은 합성 응답으로 대체한다. 생산 데이터 수정과 외부 모델 호출은 하지 않는다.

검사 결과는 `docs/verification/functional-parity-2026-09-21/`에 기록한다. 전체 원본 기능의 실제 서비스 종단간 검증이나 검색 품질 평가를 뜻하지 않는다.
